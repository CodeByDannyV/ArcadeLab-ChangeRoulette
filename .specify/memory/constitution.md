# Network Change Roulette (CR) Constitution

## Core principles

1. **Technical truth.** Evaluate authored change evidence against a documented networking model. Invalid content stops play. Independent fixtures establish correct, incorrect and boundary outcomes.
2. **Explanatory feedback.** Show the evidence before grading. Trace each outcome to a rule and offer a method hint and worked solution. Count viewed help separately from first-try success.
3. **Honest progress.** Require a valid exact-set prediction and permit retries. Reject duplicate commits, advance explicitly, confirm restart and reset on reload.
4. **Access.** All core actions work with visible keyboard focus. Replay has text outcomes and respects reduced motion.
5. **Deterministic grading.** Use local static content. States and allowlists determine the grade. Cosmetic reveal order may vary.
6. **Separation.** Keep editable content, policy evaluation, session state and rendering separate.
7. **Evidence.** Ship the agreed scope and document actual verification.

## Governance

Keep the constitution, feature documents and README aligned. Record scope or model changes and review their effect on fixtures and acceptance criteria.
